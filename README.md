# StudyRoute

Персональный навигатор обучения AI/Data. Работающий локальный проект для портфолио: Python, HTTP API, браузерный интерфейс, тесты и готовый пример отчёта.

## Быстрый запуск на Windows

1. Полностью распакуйте ZIP в отдельную папку. Не запускайте файлы внутри архива.
2. Установите Python **3.11 или 3.12** с python.org (с Python Launcher `py`).
3. Дважды нажмите **START_WINDOWS.bat** и дождитесь строки с адресом сервера.
4. Откройте **http://127.0.0.1:8014** в браузере. Окно консоли оставьте открытым.
5. Для остановки нажмите Ctrl+C в консоли.

При первом запуске создаётся `.venv` и устанавливаются зависимости. Сторонних Python-зависимостей нет; интернет для локальной работы не требуется. Сам Python в ZIP не включён. Если окно сообщает об ошибке, оставьте его открытым и прочитайте сообщение. Если порт занят, запустите `python app.py serve --port 8111` из терминала и откройте указанный адрес.

## Запуск из терминала (Windows / macOS / Linux)

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py serve
# macOS / Linux вместо этого:
# .venv/bin/python -m pip install -r requirements.txt
# .venv/bin/python app.py serve
```

Все дальнейшие команды `python` выполняйте интерпретатором созданного окружения.

## Что реализовано

- Профили слушателей и 3 цели: Data Analyst, ML Engineer, AI Product Specialist.
- 6 тем, 18 диагностических вопросов и 18 отдельных контрольных вопросов.
- Порог 2/3 и граф prerequisites; тема не засчитывается без подтверждённых основ.
- Краткие материалы, практические задания и ссылки на первичные источники.
- После контрольной маршрут пересчитывается: освоенные темы, доступные и заблокированные шаги.
- Объяснение выбора темы и ориентировочная оставшаяся длительность.
- При провале повторной проверки основы зависимые темы теряют статус освоенных.
- История попыток, ответы, результаты и прогресс сохраняются в SQLite.

## Демонстрация за 2–3 минуты

1. Создайте профиль с целью ML Engineer и пройдите диагностику (18 вопросов).
2. Сравните ответы с пояснениями и посмотрите, почему темы доступны или заблокированы.
3. Откройте материал доступной темы и решите практическое задание.
4. Пройдите отдельную контрольную (3 вопроса).
5. Посмотрите, как изменился маршрут и история.
6. Перезапустите приложение: профиль и прогресс сохранятся.
7. Готовый автоматический пример маршрута: `reports/example/route_demo.json`.

## Готовые результаты и повторный запуск

В `reports/example/` уже есть JSON и `REPORT.md` с результатами выполненного локального прогона. Данные синтетические, результаты не выданы за работу с клиентами.

```bash
python app.py demo
python -m unittest discover -s tests -v
```

`demo` пересоздаёт файлы в `reports/example/`. Пользовательские данные интерфейса остаются в `storage/app.sqlite3`. Чтобы начать с нуля, остановите сервер, при необходимости сделайте резервную копию и удалите только папку `storage/`.

## Структура

- `app.py` — CLI и HTTP-маршруты.
- `core.py` — предметная логика и работа с результатами.
- `common.py` — сервер, SQLite, поиск и клиент API (используются нужные проекту части).
- `web/` — HTML, CSS, JavaScript без CDN и сборщика.
- `data/` — исходные демонстрационные данные.
- `tests/` — автоматические проверки.
- `docs/` — описание продукта, API и сценарий дальнейшего тестирования.
- `.github/workflows/tests.yml` — конфигурация CI для Python 3.11/3.12.

## Ограничения

Это система рекомендаций по правилам, без LLM. Три вопроса на тему — грубая диагностика, а не доказательство компетенции. Вопросы и материалы ограничены; правила, порог и длительности заданы вручную. Не учитываются забывание, свободные ответы и практический код. Контрольные вопросы можно повторять, поэтому запоминание ответов возможно. Измерен автоматический сценарий работы, добровольцы в тестировании не участвовали. При снижении оценки prerequisite нужно повторно подтвердить зависимые темы.

Приложение слушает только `127.0.0.1`, рассчитано на одного локального пользователя и не предназначено для публичного размещения без доработки сервера, авторизации и обработки нагрузки. Секреты не включены. Windows BAT и реальные внешние LLM отдельно не запускались; подробности фактических проверок — `docs/VERIFICATION.md`.
